---
title: the repo was the wrong source of truth
date: 2026-08-06
summary: repository scanning mapped real design languages, then exposed the difference between implementation evidence and authored intent.
---

The first ghost assumed a shared UI library would sit at the center of the system. Products would adopt it, change their copies, and publish enough information for ghost to compare how the fleet evolved.

This assumption created a time problem. A new component library can take years to reach the products where its observability would matter. ghost needed to work across the implementations that companies already had, without requiring them to replace their stacks first.

So I started asking whether an agent could inspect any frontend repository, infer its design language, and build the drift mechanism from there. The scanners worked.

## scanning what had shipped

The scanning work became independent of one UI library or framework. ghost inspected repositories, found their visual and structural signals, and generated comparable fingerprints. I used it across several real frontend codebases and produced visualizations of their design languages.

Those views were useful. They showed relationships that had been hard to see across products. They could reveal clusters, divergence, and the different visual systems that had formed over time. The original observability idea worked without requiring every product to adopt the same component source.

This success exposed the problem with the direction.

A scanner sees implementation. It has no way to know which parts of that implementation are right according to the brand. It can't tell whether a repeated pattern expresses deliberate intent, survives because nobody has touched the code in five years, or exists because a deadline forced a compromise. When the repository is the evidence, every shipped choice arrives with the same apparent legitimacy.

The approach favored mature products. ghost needed enough code to inspect before it could infer a useful design language. The richest signal therefore carried the most history: deliberate decisions mixed with migrations, local fixes, and technical debt.

We were trying to derive a source of truth from the accumulated consequences of not having one.

## the components did not contain the picture

This limitation reaches beyond scanners.

Design systems often give an agent a component library and documentation written for humans. The components tell it which pieces exist. The documentation explains APIs, variants, tokens, and some broad principles. A human designer brings years of additional context to that material. They know which compositions feel plausible, which rules bend in a high-trust moment, and which valid arrangement would never ship.

An agent doesn't inherit that context from the component code.

Giving it 30 components is like giving it a jigsaw puzzle without showing the final picture. It can assemble the pieces in millions of valid ways. Only a small subset will feel like the brand.

The missing context often concerns composition: why one action sits on the right, why a dense workflow resists cards, why checkout removes decoration, or why one product explains a risk before asking for commitment. None of those decisions live inside a button by itself.

Loose guidance leaves the model to complete the picture from its training. It fills each gap with a common interpretation: familiar layouts, familiar phrases, familiar hierarchy, familiar AI product styling. A polished result can still be an average assembled from patterns that belong to everyone.

ghost needed to carry the decisions that keep a model out of that median.

## from design language to brand

The repository lesson changed the question. Instead of asking how an agent could infer a brand from what a product had shipped, I started asking how people could author the best portable brand artifact for an agent before it made anything.

This artifact couldn't stop at interface design. I believe product is an extension of brand. The same company expresses a stance through its product behavior, marketing, emails, words, trust decisions, social presence, and images. Those expressions have belonged to separate teams with separate documents, and the seams show.

Agents make those organizational boundaries less useful. An agent writing an error state may need product behavior, voice, accessibility, and trust guidance at once. An agent making a campaign page may need visual composition and the same stance toward customer claims. The task determines the context, not the department that authored each document.

This broadened ghost from a developer tool into work that overlaps brand design, product design, writing, engineering, and other disciplines. The packet's boundary became practical: if something helps a model produce an on-brand output or helps judge whether the output is right, it may belong.

The medium could be code, words, or images. Our evaluation today concentrates on raw HTML and CSS, so the broader range remains an ambition we need to test rather than a finished claim.

## authored, portable, optional

Moving toward authored intent raised a concern. ghost began as a challenge to centralized control. Would an authoritative brand packet recreate the same bottleneck in a different file format?

The packet keeps the original copy-and-own premise. Its authors can publish a starting point without controlling every product that adapts it. The fuller decentralization argument belongs in [drift was the point](../2026-08-06-drift-was-the-point/).

The scanner taught us something we couldn't have learned by dismissing it early. Repositories contain valuable evidence. They can show what a brand has become in practice and point authors toward concrete materials. They can't decide which historical choices deserve to steer the next generation.

Context has to be authored.
