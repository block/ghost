---
title: designing the selection system
date: 2026-07-18
summary: gather and pull make guidance selection explicit so agents can take the context a task needs and authors can see what entered the work.
---

A useful brand package needs a lot of context.

Brand shows up through product behavior, composition, words, trust, marketing, email, images, and the small choices that connect them. A package broad enough to steer all of that cannot become one prompt pasted into every task.

The context window constrains you. Relevance constrains you more. A brand can hold guidance that looks contradictory because each statement belongs to a different medium or situation. A quiet product flow and an expressive campaign may both be right. A high-trust financial action and a casual social post should not use the same density, language, or persuasive moves.

People resolve these differences from context. They browse documentation, recognize which part concerns the work, and return to it when a new decision appears. A model without that shared history needs the package to make the process explicit.

That is what gather and pull are for: give the agent the right context at the right time.

## gather is the menu

`ghost gather` presents the complete menu of guidance in a package. Each item has an id and a description that tells the agent what it covers and when it applies. The menu stays compact enough to inspect without loading every node body and material into context.

The host agent reads that menu against the task. It uses `ghost pull` to retrieve the applicable nodes, including their prose and concrete materials. It can return and pull more guidance as the work develops.

The pair mimics how a documentation site works. Nobody pastes the whole site into working memory before designing a page. You see the available sections, open the ones that matter, start working, and consult another section when the task reaches it.

This interaction changes how authors write the package. A description is not a summary added for convenience. It is the retrieval payload. It needs to name the condition under which the guidance should enter the work. Topic overlap alone is not enough. Guidance about trust may apply to one irreversible action and not to every screen that contains money.

The body can carry the full context without forcing it into a universal prompt.

## ghost stops before the agent

ghost does not decide which nodes apply. It emits the menu and retrieves the ids the host requests, leaving responsibility with the host agent.

ghost should not become another agent implementation. It should work across models, harnesses, editors, and future making loops. The host already knows the task, the conversation that led to it, the files being changed, and the medium it will produce. A separate ghost agent would duplicate that context and bind the package to one interpreter.

ghost handles the repeatable work: validate the package, expose the complete menu, retrieve selected guidance and materials in a stable order, and record what happened locally. The installed skill teaches a capable host how to judge applicability.

This boundary keeps the brand artifact portable. A team can improve its package without choosing the same model or agent harness as every consumer.

## selection is evidence

gather is also an observability tool.

Before selection events, a generated output could be wrong without showing why. The package might lack the right guidance. The menu might describe it poorly. The agent might skip it. The model might receive it and fail to follow it.

gather and pull record which guidance was exposed and which nodes the agent requested. The trace doesn't grade the output. It gives the author evidence about the context that participated in making it.

Internal testing surfaced cases where agents pulled unexpected guidance or missed guidance that seemed central. Those results showed that parts of the descriptions and organization were off. The glossary and node applicability changed, then the tests ran again.

The final output alone couldn't have shown what to change. Selection made the authoring problem visible.

The feedback loop gives the package a way to improve through use:

1. An author states guidance and describes when it applies.
2. An agent reads the menu and pulls a subset for a real task.
3. The local event trail shows what it used and missed.
4. The author revises the package or glossary where the selection was wrong.

## context has a cost

Selective context has an economic effect.

There is no published evaluation of the context savings yet. The pieces are measurable: menu size, selected-node size, selection traces, run cost, and output comparisons.

The goal is not context minimalism. Some tasks need many nodes, and a serious brand package should contain enough depth to change the work. gather gives the agent a way to take what the task requires without pretending one universal prompt can represent the whole brand at once.
